# 变更日志（Changelog / Release Notes）撰写规范与准则

## 一、核心定位与基本原则

变更日志是**产品与终端用户对话的窗口**，其本质是向用户交付产品价值，而非向开发者汇报开发过程。

| 维度 | 对外变更日志（Release Notes） | 对内研发记录（Git Commits / PR） |
| :--- | :--- | :--- |
| **受众** | 终端用户、产品运营、外部协同人员 | 开发人员、测试人员、代码审查者 |
| **视角** | **用户价值视角**（我能用什么？体验有什么提升？） | **工程实现视角**（改了哪行代码？修了哪个变量？） |
| **时态基准** | **对比上一公开发布版本**（如 v1.0.4 → v1.1.0） | 任意开发中间提交（Commit by commit） |

---

## 二、“三大严禁”红线原则

### 1. 严禁收录「当期开发过程中的自测修复 (WIP Fixes)」
- **判定标准**：如果一个 Bug 是在本次新功能开发过程中产生的，并在本次发布前已被修复，**这属于新功能交付的合格标准，绝不是“修复项”**。
- **负面影响**：写出来会让用户感到困惑（“这功能之前根本没有，怎么就修复了？”），暴露出研发未自测完备即对外传达的负面印象。
- **唯一合法的修复定义**：**只有上一公开版本中真实存在、用户可能踩过坑的历史线上缺陷，才可列入“修复”**。

### 2. 严禁暴露「底层实现细节与代码黑话」
- 避免直接抛出组件名、类名、数据结构、内部方法名等（如 `Form.Item`、`useEffect`、`Tailwind class`、`z-index`、`类型定义`）。
- 转换为**用户能感知的界面表现、交互行为与视觉质感**。

### 3. 严禁事无巨细、过度冗长
- 保持在 **3 ~ 6 条核心要点** 左右；
- 避免把一句话拆解成技术细节的层层汇报，扫一眼（Glanceable）即知核心变化。

## 三、标准分类体系与动词规范

采用统一的类别标记与前置动词，降低用户阅读心智负担：

| 分类标识 | 适用范围 | 推荐动词前缀 |
| :--- | :--- | :--- |
| ✨ **新增 (New)** | 上一版本完全不存在的全新页面、新功能或独立模块 | **新增**…… / **支持**…… |
| 🎨 **优化 (Optimized)** | 对既有功能的体验优化、视觉重构、性能提速、文案规整 | **优化**…… / **升级**…… / **重构**…… |
| 🐞 **修复 (Fixed)** | **仅限前一线上公开发布版本**已存在的用户可见缺陷 | **修复**……问题 / **解决**……导致的异常 |
| ⚠️ **调整 (Changes)** | 影响用户固有习惯的调整（如默认快捷键变更、数据存储迁移） | **调整**…… / **变更**…… |

## 四、正反案例对比（Bad vs Good）

### 案例 1：开发阶段的内部 Bug 处理
- ❌ **错误（Bad）**：
  > 修复编辑倒数日时，“置顶到桌面胶囊”开关状态未正确读取与保存的问题。  
  > *（原因：倒数日是本版本才加的新功能，用户从没见过这个 Switch，写出来是无效噪音）*
- ✔️ **正确（Good）**：
  > **直接删除该条目**。确保在“新增倒数日”或“桌面胶囊”的主描述中功能体验完整即可。

### 案例 2：底层技术重构的表述转换
- ❌ **错误（Bad）**：
  > 重构了 Clock 组件的 getFontFamilyStyle 和 getFontWeightStyle，加入 Cascadia Code、Noto Serif SC 回退，并将 thin 映射为 fontWeight 200。  
  > *（原因：纯代码实现汇报，普通用户看不懂也不关心）*
- ✔️ **正确（Good）**：
  > **时钟字体与字重全面升级**：优化字体族谱与渲染逻辑，全风格（Mono、Serif、Round 等）现已完整支持「纤细极简」细体。  
  > *（收益明确，点出真正解决的用户痛点）*

### 案例 3：视觉间距调试的表述转换
- ❌ **错误（Bad）**：
  > 将倒数日胶囊容器改为 w-[240px]，使用 justify-between 对齐，添加 tabular-nums 类。
- ✔️ **正确（Good）**：
  > **视觉与排版规整化**：胶囊统一定宽与两端对齐，搭配等宽数字与毛玻璃质感，避免错落锯齿，视觉更平衡。

## 五、推荐发布模板

```markdown
### 🚀 v{X.Y.Z} 更新日志 ({YYYY-MM-DD})

- **新增「{功能名称}」**：
  - 简述核心能力 1（如支持的操作、分类、智能预设等）；
  - 简述核心能力 2（如联动展示、桌面小组件等）。
- **视觉与体验优化**：
  - 简述视觉提升（如排版齐平、毛玻璃质感、统一图标集）；
  - 简述交互细节（如移除干扰动效、优化悬停反馈）。
- **字体与性能升级**（若有重点）：
  - 简述升级收益（如全风格支持极细字重、启动速度提升）。
- **问题修复**（仅限存量线上已发版本 Bug）：
  - 修复 [旧版本已有功能] 在 [特定场景下] 的 [异常表现] 问题。
```
